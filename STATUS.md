Standing rule, in Dustin's words: **use Apple's guidelines whenever possible.** No one-offs: fix the pattern, not the instance. Pass tests force the failure state; they don't wait for it to happen by luck. Device pass tests are walked **one action at a time**: "Do: … / You should see: …", then wait, and only about what is on the screen now — a later result proves the earlier steps. Put the common action **on the row**, visible; the long-press menu is the backup.

Harness facts worth knowing: Xcode 27 has no Simulator.app, the Duo simulator only shows the folded panel, so regular-width checks run on the iPad Air sim and the real look is checked on Dustin's devices (`DBd` iPhone, `Dustin's iPad (3)`). One device-interaction session at a time; check the run destination before any run (it has been his phone and his iPad; a locked device makes every test "No result"). **Run the unit tests on the Duo simulator**: two `QuietSyncTests` need the iPhone idiom (`isGradingDevice`) and fail on the iPad sim by design. The app target's folders are plain Xcode groups and a hook blocks direct `project.pbxproj` edits: create new files with `XcodeWrite` into an existing group and Xcode adds them to the target itself. **In-memory test stores must say `cloudKitDatabase: .none`** — on the iOS 27.1 simulator runtime the default picks up the iCloud entitlement and every save throws "No eligible connection available". **The full test plan runs the UI tests alongside the unit tests on the one simulator**, relaunching the app over and over; `HabitSyncEngine.isUnderTest` keeps the host app's own on-open sync out of the way. The simulator ignores a synthesized power button, so lock-the-phone behaviour is proven on DBd only. When Dustin texts from the phone during a pass, every return to the app after two minutes is an "open" run that overwrites the Developer "Last run" line — have him read the line inside the app before switching away. The iPad sometimes refuses the first install (locked); a second `RunProject` lands it. If there is doubt whether a build landed, have Dustin open a screen only the new build has (a new Settings row) rather than judging by looks — on 2026-10-29 "old UI" turned out to be the unchanged Journal tab; `xcrun devicectl device install app` with the Debug-iphoneos bundle is a sure reinstall and prints a new container id as proof.
