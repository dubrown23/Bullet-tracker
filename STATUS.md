## Where we are

Bullet Tracker is a working personal habit app on SwiftData + CloudKit, brought up to the iPhone Duo and Apple's current design language over 2026-10-24/25 (`bt-0008` → `bt-0016`): iOS 26 target, size-class-aware layout, system chrome everywhere, the **week-grid** Today row, one **win rule**, a consistency pass, and a **tappable tile-grid widget** Dustin confirmed on his Duo.

On 2026-10-26/27 the long-planned merge with **Dustin's Health** went from design to live in three beads. The design (shared note `~/Desktop/Personal/dustin-system/memory/in_flight/habits-voice-dh-bullet-2026-10-26.md`): Dustin talks to Claude on his iPhone; voice lands in dustin-health (dh) as day facts + an inbox of actions; **Bullet pulls and grades everything itself**. `bt-0017` (Step 0) proved the pipeline with fake data. `bt-0018` (Step 2) added the rules: a neutral **Rest** grade, **targets as habit settings** with a stamped go-live day, **Today in progress**, and a **source** (auto / hand / voice) on every entry so hand grades win until "Back to Automatic", with **only the iPhone writing automatic grades**. **`bt-0019` (Step 3) is live:** the iPhone holds the app's key to dh in its Keychain and syncs on open and on pull-down; the real Diet and Workout are graded from real data from 2026-10-27 forward; the iPad never calls dh. **`bt-0021`** made the two graded rows legible (the Today caption says Auto / Set by you / Set by voice with Back to Auto on the row; Log Details shows dh's meals and sessions from a `health` key beside the notes) and **`bt-0020`** made hand taps reach dh by themselves (one hook at the end of the three store writes, a 3 s timer every tap restarts, leaving the app sends at once, two on-disk dates beat the on-open throttle; the Developer screen's Last run line says why each run happened).

**2026-10-28 evening: the data for the new Dashboard exists (`bt-0022`), and avoidance habits read honestly (`bt-0024`).** Dustin is retiring the dh website dashboard, so the Bullet Dashboard has to show one day's nutrition and training plus habit trends; `bt-0022` built what it stands on. Backup now round-trips the `health` block; the sync stores **steps per day** on the Workout row; **carbs / fat targets** live on the Diet habit and go up to dh; and a one-time, phone-only **Prepare Dashboard History** screen (gated on a backup saved to Files, counts on screen, one confirm) **wiped every habit's rows before 2026-10-27 except Poison, and rebuilt Workout from dh's sessions alone, Aug 1 → Oct 26** (graded by the Workout rule with steps and the current targets, `source = auto`, go-live stays Oct 27). It ran on DBd; the Journal shows the rebuilt days (Sept 15: Workout, Cardio + Strength, 67 min) and the iPad carried it. The wipe exposed **Weed with a 365-day streak**: the win rule counted a clean avoidance day as a win and the streak walked back a year. Dustin's call, the same evening: **only slips get marked.** `bt-0024` made an avoidance habit never a win and never a streak; a clean day is an empty square and adds nothing to the header; the rate shown beside a good habit's done rate is a **slip rate**, "N% slipped · N days" (slip days over scored days, lower is better, red bar), on the Dashboard row, the detail page and the PDF; the overall Completion % counts positive habits only, so a slip never lowers it. 91 tests. Simulator pass 6/6, Dustin's pass on real data. **Poison is a simple habit** (dh `kind = simple`), untouched by `bt-0024`; Weed and Alcohol are the avoidance ones.

Standing rule, in Dustin's words: **use Apple's guidelines whenever possible.** No one-offs: fix the pattern, not the instance. Pass tests force the failure state; they don't wait for it to happen by luck. Device pass tests are walked **one action at a time**: "Do: … / You should see: …", then wait, and only about what is on the screen now — a later result proves the earlier steps. Put the common action **on the row**, visible; the long-press menu is the backup.

Harness facts worth knowing: Xcode 27 has no Simulator.app, the Duo simulator only shows the folded panel, so regular-width checks run on the iPad Air sim and the real look is checked on Dustin's devices (`DBd` iPhone, `Dustin's iPad (3)`). One device-interaction session at a time; check the run destination before any run (it has been his phone; it is on the Duo simulator at the end of this session). The app target's folders are plain Xcode groups and a hook blocks direct `project.pbxproj` edits: create new files with `XcodeWrite` into an existing group and Xcode adds them to the target itself. **In-memory test stores must say `cloudKitDatabase: .none`** — on the iOS 27.1 simulator runtime the default picks up the iCloud entitlement and every save throws "No eligible connection available". **The full test plan runs the UI tests alongside the unit tests on the one simulator**, relaunching the app over and over; `HabitSyncEngine.isUnderTest` keeps the host app's own on-open sync out of the way. The simulator ignores a synthesized power button, so lock-the-phone behaviour is proven on DBd only. When Dustin texts from the phone during a pass, every return to the app after two minutes is an "open" run that overwrites the Developer "Last run" line — have him read the line inside the app before switching away. The iPad sometimes refuses the first install (locked); a second `RunProject` lands it. If there is doubt whether a build landed, have Dustin open a screen only the new build has (a new Settings row) rather than judging by looks — on 2026-10-29 "old UI" turned out to be the unchanged Journal tab; `xcrun devicectl device install app` with the Debug-iphoneos bundle is a sure reinstall and prints a new container id as proof.
