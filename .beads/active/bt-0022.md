# Dashboard history — the data the new Dashboard stands on

Design pass 2026-10-28 (this file is the record). The Dashboard rewrite is
`bt-0023`; it cannot render history that doesn't exist, so this bead goes
first. **Ends with Dustin's yes on the phone and the wipe run.** The dh
website dashboard stays on until `bt-0023` passes side by side on his phone.

## Why

Dustin is removing the dustin-health website dashboard
(`public/dashboard.html`, `lib/dashboard-data.js`). The Bullet Dashboard
replaces it, so it has to show one day's nutrition and training the way the
site did, plus habit trends. Three things the data can't do today:

1. **Backup drops the `health` block.** `BackupManager.fetchHabitEntries`
   writes `entry.details` through the typed enum, so dh's meals / sessions
   never make the round trip. The Dashboard's history now depends on that
   block, and the wipe below is gated on a backup, so this ships first.
2. **Steps aren't stored.** The sync reads steps from Apple Health for the
   7-day window on every run but only uses them to grade. The Dashboard
   wants steps per day, on the iPad too (no HealthKit there).
3. **No history before go-live for Workout, and the wrong history for
   everything else.** Dustin's decision: a clean start on 2026-10-27 for
   every habit except Poison (kept whole) and Workout (dh's record alone,
   from 2026-08-01).

## Decisions (Dustin, 2026-10-28)

| Habit | Before Oct 27 |
|---|---|
| Poison | Everything kept |
| Workout | Deleted, then rebuilt from dh for Aug 1 → Oct 26: a row only on days dh has a session, graded by the Workout rule. No-session days blank. Nothing before Aug 1. |
| Every other habit (Food, Weed, Alcohol, …) | Deleted |
| Journal notes | Kept, never touched |

- Habit list, order, colours, settings and targets all stay.
- Everything from Oct 27 on stays exactly as it is. **Go-live stays Oct 27.**
- Imported Workout days: steps lift a short-session day to Partial (same
  rule as today); the **current** minutes target applies to the whole span.
- Carbs and fat targets are **owned by Bullet** on the Diet habit and sent
  up to dh like protein and calories. They colour rings only; not part of
  the win rule.
- Day picker on the Dashboard: the shared 7-square strip (for `bt-0023`).
- The wipe cannot be undone in the app: backup first, counts on screen,
  one confirm.

**New per-session fields** (dh `b7d3b5c`, live), to decode in
`DustinHealthSource` and store in `HealthSnapshot.Session`:

- `active_kcal` — Watch active calories summed over linked records; `null`
  when missing → show a dash, never 0. (The dh website shows 0 for the same
  case; expect that difference in the side-by-side pass.)
- `activity_type` — Apple's name on the primary Watch record. Names differ
  by source ("Indoor Run" vs "Running"), so the Workout chips light by a
  name map, not an exact match.
- `activity_code` — Apple's number, present on only 24 of 141 sessions
  since Aug 1. Don't rely on it.

### 1. Backup round-trips the stored string

Back up `detailsJSON` as it is (already the legacy wire shape plus the
`health` key) and restore it as-is. Keep the typed parse only for backups
made before this fix (no raw string present). One round-trip test: a row
with notes + health → export → import → same `health`.

### 2. Steps stored by the sync

`HealthSnapshot` gains `steps: Int?`. The grading pass that already has
`stepsByDay` writes the day's steps into the Workout row's block through
`setHealth` (unchanged rules: never touches state / source / edit time,
writes only on change). Yesterday's final count lands on the first run
after midnight; a week of late Watch samples is picked up.

### 3. Carbs + fat targets — gate OPEN (dh `b7d3b5c`, live 2026-10-28)

`Habit.targetCarbsGrams` / `targetFatGrams` (optional, nil = default 180 /
65), two rows in the Diet grading section of the form. Not used by
`DietGrade`.

dh accepts `carbs_g` and `fat_g` in `op=sync` targets: grams, optional,
`null` clears one, range 0–1000; the `targets` reply carries both keys
(`null` until set). The voice target tool can't set them. **Send them
directly** — no local-only phase. One test: the targets payload carries
the seven keys, with `null` for an unset carbs / fat. (dh still rejects
any key it doesn't know — `api/bullet.js:59` — so no other new key goes
on the wire without the same dance.)

### 4. Workout import (phone only, once, inside the wipe screen)

- Facts for Aug 1 → Oct 26; steps from HealthKit for the same days.
- **Sessions only.** Meals in the same response are ignored. No Diet row,
  no meals block, for any day before Oct 27. Tests: (a) a facts set with
  meals and sessions on the same days → no Diet row before Oct 27;
  (b) Workout rows carry sessions and no meals.
- Per day with ≥ 1 session: write a row, `source = .auto`, state from
  `WorkoutGrade.state(minutes:steps:targets:)` with the current targets,
  health block = sessions + steps.
- Days with no session: nothing.
- Before go-live the row shows no Auto / Set by you caption and no Back to
  Auto (existing `isWithinGrading` guard); Log Details lists the sessions
  under "From Dustin's Health". The ordinary run's cleanup touches only
  days it graded plus today, so imported rows are never revisited.
