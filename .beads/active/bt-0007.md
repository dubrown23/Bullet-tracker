# Pre-existing data integrity — HabitEntry records with null `completionState`

## Why

Surfaced 2026-05-14 during `bt-0005` Pile B verification run. When the app launches, the Xcode console floods with 100+ Core Data validation errors of the same shape:

```
Error Domain=NSCocoaErrorDomain Code=1570 "%{PROPERTY}@ is a required value."
entity: HabitEntry; NSValidationErrorKey=completionState; NSValidationErrorValue=null
```

And SwiftData's CloudKit mirror reports:

```
CoreData+CloudKit: <NSCloudKitMirroringDelegate> - Never successfully initialized
and cannot execute request '<NSCloudKitMirroringExportRequest>' due to error:
Multiple validation errors occurred.
```

What's happening: `bt-0003` Phase-2 migration collapsed completion state into a typed `CompletionState` enum and made it required (non-optional) on `HabitEntry`. The wipe + restore migration was supposed to ensure all entries had valid `completionState` values. Either the migration left some entries with `null` `completionState`, OR CloudKit pulled in old data from another device's store that pre-dates the migration. ~100 entry IDs visible in the error log (`p847` through `p981` range), suggesting a contiguous block of legacy entries.

The app **functions normally** — Today/Dashboard/Journal render + interact (verified during `bt-0005` simulator run). Only background CloudKit sync is choking. Nothing user-visible is broken.

This is **pre-existing**, not caused by `bt-0005` — first observed during the Pile B verification run, which was the first end-to-end app launch since the `bt-0003` ship on 2026-05-13. The errors have been silently failing CloudKit sync since the migration; they only became visible when Dustin ran the app for Pile B's verification gate.

## Out of scope

- Any `bt-0005` Pile B work (already shipped 2026-05-14).
- UI changes — the user-facing surface works fine; this is sync/data hygiene only.
- Schema changes — the schema is correct per `bt-0003` Phase 2; the issue is data conforming to the schema.

## Plan
