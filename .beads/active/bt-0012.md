# Design sweep (after Waves 1–3, before the widget)

## Why

With the structural and guideline work done (`bt-0008`–`bt-0010`), Dustin asked for an overall design look. Fresh-eyes review of every screen (2026-10-25, Duo + iPad sim shots): the app is now mostly standard system UI; the remaining weak spot is the **Today row**, which is the one surface the app lives on. Plus two checks nobody has run yet: **dark mode** and **colour contrast**. Approved 2026-10-25, sequenced before `bt-0011` so the widget's circles can match the new row.

## Out of scope

- Widget (`bt-0011`, next).
- Behaviour changes (Done-saves-record question still parked).
- Journal, Settings, Backup, Log Details, New Habit layouts beyond the specific items below — they're standard Apple layouts and read cleanly.

## Plan

1. **Today row redesign** (`TodayHabitCardView`). One shape per row: the icon tile *is* the button (44pt, `@ScaledMetric`). Not done → tinted tile with the habit icon. Done → tile fills with the state colour (simple: habit colour; multi-state: green/orange/red; avoidance slipped: red) and a white state symbol (checkmark / half / xmark) replaces the icon — the Reminders pattern. Last-7-days dots → 8pt rounded squares, right-aligned as the trailing-most element so every row's strip lines up into a 7-day grid. Streak badge and ⓘ sit between name and strip. AX text sizes still stack.
2. **Slimmer Today summary** (`TodayView`): ring 44pt, tighter padding; same content.
3. **Dashboard period picker** out of its white card (`.listRowBackground(.clear)` + no insets) so it reads as a control, not content.
4. **Habit form icon section** (`HabitFormView`): the icon tile is the button that opens the picker; drop the "Change" text; keep the quick-icon row.
5. **Dark mode pass**: every screen on the Duo sim in dark appearance; fix anything hard-coded or unreadable.
6. **Contrast audit**: Apple's Sufficient Contrast checklist on the row, journal, heatmap, chips, swatches; fix failures (expect `.tertiary` text and white-on-pale-colour).
7. Build; verify Duo sim (light + dark, default + AX text) and iPad sim, one session at a time; install on Dustin's Duo; ship.

## Decision log

- 2026-10-25 — shipped. Final fix: the delete-confirmation alert moved from the row to `TodayView` (`habitToDelete` + one `.alert(presenting:)`); the row just calls `onRequestDelete`. Reason: when a swipe action fires, List tears the row down and any presentation owned by row `@State` vanishes within ~1s (verified: alert drawn, never interactive). Re-verified on the Duo sim: swipe → red Delete → real alert with Cancel / Delete Habit; Cancel keeps, confirm deletes, no fall-through; context-menu path shows the same alert. Known minor leftover: on iPad the context-menu lift preview of a lone (odd) paired row spans the full row, not just the visible half.
- 2026-10-25 — **bug found by verification: habits could not be edited or deleted from the UI.** `TodayViewModel.selectedHabit` drove the Edit sheet but nothing ever set it; the Dashboard detail has no Edit. Added the three standard routes on the Today row: tap the name → `EditHabitView`; long-press context menu (Edit / Delete); trailing swipe actions (Edit / Delete). Delete confirms via an `.alert` (first try was a `.confirmationDialog`, which on the Duo rendered as a popover anchored to a row that had just been swiped — ghost popover, tap fell through to the row below). Removed the dead sheet in `TodayView`. Swipe Delete needs an explicit `.tint(.red)` because the app-wide accent tint overrides the destructive red.
- 2026-10-25 — verification round 1 (Duo + iPad): new row PASS in light and dark (tile fills, ✓/◐/✕ with black-or-white symbol, strips right-aligned, streak primary), Dashboard picker bare, Journal selected cell black-on-orange, chips contrast-aware. Fixed from the round: icon row's empty middle wasn't tappable (`contentShape`), lone paired row's strip 8pt off (hidden `Divider` twin), streak count grey when done → primary.
- 2026-10-25 — **dark-mode audit** (Duo sim, 15 screens): clean. One defect: habit-detail period label had a conditional `.secondary` tint that read as disabled → made plain. Also seen: Export Journal sheet's Cancel/Export scroll away → `keepNavigationBarVisible()` applied there too. Side note from the run: tapping Done in Log Details on an unchecked habit marks it done (consistent with `updateEntryDetails(state: 1)`); still Dustin's call.
- 2026-10-25 — **contrast audit** (WCAG 2.1 via Apple's Sufficient Contrast checklist, computed from the hex values): FAILs were (a) `.tertiary` text (~2.2:1): note-row time, heatmap M/W/F labels → `.secondary`; (b) coloured *text* — orange/green stat values, habit-colour completion %, orange streak count (2.2–2.3:1) → primary text, colour kept on icons (Apple Health pattern); (c) white on the orange accent / habit colours — selected day cell, selected chips, filled tiles (white on `#FF8C42` = 2.3:1) → `AppTheme.readableForeground(onHex:)` picks black or white by WCAG luminance, so pale colours get dark symbols. **Deliberately left:** the accent itself as a *control* tint (buttons, chevrons, links) — Apple ships system orange the same way; changing it is a brand decision for Dustin. Progress-bar fill vs track (~1.9:1) left: the % text beside it carries the value.
- 2026-10-25 — created; branch `bt-0012-design-sweep` off `bt-0010-design-language` (bt-0010 not yet merged to main — awaiting Dustin's device look).
