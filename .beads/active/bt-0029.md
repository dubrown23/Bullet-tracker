# Workout's steps-only day becomes its own orange "Active day"

Spec from Dustin 2026-11-10, build authorized without a plan stop.

## Why

The automatic "no workout, but steps ≥ target" Workout day shared Diet's
yellow Partial, so a walking day and a half-kept diet looked the same.

## Plan

- New `CompletionState.activeDay = 5` (additive raw value, nothing
  renumbered). `WorkoutGrade` writes it where it wrote `.partial`; same rule,
  same automatic grading. Diet's Partial untouched; voice "partial" still
  writes Partial.
- Scores like Rest: neutral (`HabitWinRule.isNeutral`) — streaks carry
  through, rates and the heatmap leave the day out.
- Orange (`AppTheme.activeDay`, the accent orange), walking-figure symbol,
  named "Active day" everywhere a state is drawn or spoken (Today row and
  caption, dots, Log Details picker for the Workout habit, Journal, widget).
- A hand tap on an Active day moves to Tried, as a tap on Partial did.
- One-time pass on the iPhone: automatic (`source == auto`) Partial rows of
  a Workout-graded habit become Active day. Hand / voice rows untouched.

## Out of scope

- dh (it never grades). Diet. Any change to the steps rule itself.

## Pass

Unit tests (grade, neutral scoring, one-time pass leaves hand rows alone).

## Shipped 2026-11-10

129 unit tests pass on the Duo sim (RunSomeTests), 4 new: grade + Diet /
voice Partial untouched, neutral scoring, own orange + name, the one-time
pass changes only automatic Workout Partials (hand, voice, Diet untouched;
a second pass changes nothing). Not on a device yet: the iPad was locked,
and the iPad must get this build before the phone, because the phone's
conversion sends raw value 5 through iCloud and the iPad's Oct 30 build
doesn't know it.
