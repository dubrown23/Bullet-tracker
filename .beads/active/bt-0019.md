## The server contract (read from `api/bullet.js` + `supabase/migrations/0011_habit_inbox.sql`, 2026-10-27)

All calls: `https://dustin-health.vercel.app/api/bullet?op=…`, header `Authorization: Bearer <key>` (never in the URL). 401 = bad key, 400 = bad request, 422 = rejected by the database, 404 = unknown op.

| op | method | sends | returns |
|----|--------|-------|---------|
| `sync` | POST | `habits: [{name, kind: simple/graded/avoid, detail_kind: "reading_log"/null}]` (1–100, names unique after lower-casing and stripping non-alphanumerics), `targets: {protein_min_g, calories_min, calories_max, workout_minutes_min, steps_min}`, `time_zone`, `ticked_today: [names]` | `{habits: count, held_targets: [keys], targets: {…dh's current values…}, time_zone}` |
| `changes` | GET | `since=<ISO>` | `{days: ["YYYY-MM-DD"…], next_since: <ISO, now − 2 min>}` |
| `facts` | GET | `from=YYYY-MM-DD&to=YYYY-MM-DD` (≤ 93 days) | `{time_zone, days: [{day, meals: {count, calories, protein, carbs, fat, names}, workouts: {count, minutes, sessions: [{name, category, minutes, set_count, started_at}]}}]}` — one row per day in the range, zeros when nothing logged |
| `inbox` | GET | — | `{actions: [{id, habit, kind, day, action: tick/untick/set_grade/note/set_target, grade?, note?, book?, pages?, target_key?, target_value?, status, created_at}]}` — marks them fetched |
| `ack` | POST | `ids: [uuid]` (1–500) | `{applied: n, not_applied: [{id, reason}]}` |

Server-side rules the app leans on: a tick on a **graded** habit arrives as `set_grade done` (never a plain tick); `rest` is only ever queued for Workout; a target a voice change set and the app hasn't acked yet is **held** on `sync` (the app's older value is ignored and the key is listed in `held_targets`); habits the app stops sending go inactive on dh, not deleted; meal day = the meal's `created_at` in the sync'd time zone.

### One sync run (iPhone; the iPad runs only the steps-and-show part it has today)

0. **Gate:** a key exists and this is the grading device. Otherwise `source = nil` as now (steps only). A run also skips if the last successful run was under 2 minutes ago, except on pull-down and after Save.
1. **Steps** from Health for the window (unchanged).
2. **`op=sync`** — habits in `order`: kind = `avoid` for `.avoidance`, `graded` when `gradingKind != nil`, else `simple`; `detail_kind = "reading_log"` when `detailKind == .reading`, else `null`; targets from the Diet and Workout habits' `gradingTargets` (only the kinds that are on); `time_zone = TimeZone.current.identifier`; `ticked_today` = names of habits with a logged row today. Reply: every key in `held_targets` is written into the matching habit's target field from the reply's `targets`.
3. **`op=changes&since=`** the stored `next_since` from the last **successful** run (UserDefaults). First run ever: none → no extra days. Changed days are kept only if ≥ that habit's `gradingSince`.
4. **`op=facts`** for the union of the usual window (`max(gradingSince, today − 6)…today`) and the changed days, as one range when ≤ 93 days, else per contiguous run. Parsed into `[Date: DayFacts]` by local day; `workoutMinutes` from `workouts.minutes`; sessions kept for details. **Grade** every day as today (`grade(kind:targets:facts:steps:isToday:)` unchanged). New: an auto row for Workout also gets `.workout(types: session names, duration: "<minutes> min", …)` details; an auto Diet row gets the meal names as `.notes` if the habit's `detailKind` is `.notes`. Hand / voice rows: details untouched, as now.
5. **`op=inbox`** → apply in `created_at` order, through `HabitStore` (source `.voice`):
   - `tick` → `TickGrade.state(for: style)` (simple → done, avoid → slip). With `book` / `pages` / `note` on a `.reading` habit → `updateEntryDetails` with `.reading(bookTitle:pagesRead:notes:)`.
   - `untick` → `removeEntry` for that day.
   - `set_grade` `done` / `partial` / `tried` → `.success` / `.partial` / `.failure`. `rest` → `.rest` only if `habit.offersRest`. `auto` → `revertToAutomatic` only if `habit.isWithinGrading(day)`.
   - `note` → **details only** (Dustin's addition 3). If the day has a row, merge into its details through a new `HabitStore.mergeDetails` that touches `detailsJSON` only — state and `source` unchanged, so an auto row stays auto and the grader keeps rewriting it. If no row, write "Habit: text" as that day's Journal `Note`; no entry is created, so the automatic grade is free to colour the day later.
   - `set_target` → the habit with the matching `gradingKind` (`protein_min_g` / `calories_*` → diet; `workout_minutes_min` / `steps_min` → workout). Same write the held-targets step does.
   - A future-dated day, an unknown name, or an action that has no legal target (rest on a non-Workout habit, auto before go-live, a target with grading off) → **not applied, not acked**, listed under Couldn't apply. Dismiss acks it on purpose.
6. **`op=ack`** with the applied ids. `not_applied` reasons are shown in the report.
7. **Cleanup** (unchanged) over everything touched.
8. Store `next_since` and the status (time, counts, errors) only if 2–6 raised no transport / auth error; a failed run leaves `since` alone so the next run re-pulls.

Network: `URLSession` async/await, `Codable` payloads, 15 s timeout, errors become status text, never a crash. `HabitFactsSource` protocol grows: `sync(_:) -> SyncReply`, `changedDays(since:)`, `facts(from:to:) -> [Date: DayFacts]`, richer `InboxAction` (kind enum carrying grade / note / book / pages / target); the fake source implements the new shape trivially so the Developer screen keeps working.
