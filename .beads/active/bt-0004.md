# SwiftData data-layer perf pass — targeted predicates + dashboard calc actor

## Why

`bt-0002` Phase 1 swapped the data engine but left two known perf shortcuts in place — explicitly deferred to ship Phase 1 sooner. Both are observable in the bt-0002 Decision log as watch-items (d) and (e):

- **(d) Dashboard aggregation runs on `@MainActor`.** Wave 2 dropped the old background-Core-Data-context dance — the dashboard now does its aggregation on the main thread. Fine at current data sizes; can hitch a frame or two on the year view after years of dense data. The shape that would fix this is a SwiftData `ModelActor` (~same role as the old background context, ~30 lines).

- **(e) `HabitStore` reads filter `habit.entries` in memory.** Every fetch in the SwiftData migration is `(try? context.fetch(FetchDescriptor<X>())) ?? []` followed by an in-Swift filter. `HabitStore.entry(for:on:)`, `HabitStore.entriesByDay`, `HabitStore.allEntriesByDay`, `DayJournalViewModel.loadHabitEntries`, the widget's `fetchTodaysHabits` — all of them. For a habit tracked daily for years that means hundreds-to-thousands of objects faulted per habit per Today-list render. The shape that would fix this is `FetchDescriptor<HabitEntry>` + `#Predicate` on `habit.id` + date range, with a fetch limit. Wave 2 dodged it because `#Predicate` over optional relationships was fiddly mid-migration; standalone work it's doable.

This is **perf work, no behavior change.** The model shape stays exactly as Phase 1 left it — that's why this is its own bead and not folded into `bt-0003` Phase 2 (where the model shape *does* change, and which is blocked on the #9 Journal-intent question). Decoupling lets perf ship whenever convenient instead of waiting on #9.

There's also an indexing piece worth flagging now (not committing to scope yet): the original `.xcdatamodeld` had fetch indexes on `HabitEntry.date` and `JournalEntry.date` (named `byDateIndex`). `Models.swift` doesn't recreate them — `#Index<HabitEntry>([\.date])` would. Whether to add at design pass.

## Out of scope

- **Model shape changes.** No typing the `details` JSON blob, no collapsing the 3-way completion state, no dropping vestigial `JournalEntry` fields — that's `bt-0003` Phase 2.
- **Behavior changes.** No new features, no UX changes. Perf only.
- **Backup file format.** The `Codable` mirror structs in `BackupManager` stay byte-identical.
- **Widget redesign.** Just the data-path inside the widget's existing timeline provider + intent, not the widget's UI shape.
