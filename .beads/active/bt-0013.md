# Prototype: week-grid Today row

## Why

Dustin played with the bt-0012 row (icon tile as the checkbox) and said it feels dated and not intuitive. Survey of current habit apps: Reminders/Things = circle checklist (reads as a to-do list); Streaks = big press-and-hold tiles (hides the pattern); Everyday / Loop / HabitNow = **week grid** — habit left, last 7 days as real cells right, tap today's cell to complete. The week grid makes "log fast" and "glance at the pattern" the same gesture on the same pixels, which is the app's stated purpose. Dustin asked to judge it by feel → throwaway branch `proto-week-grid`, installed on the Duo. Keep or discard after his reaction.

## Out of scope

Everything except the Today row. No data changes.

## Plan

1. `TodayHabitCardView`: row = [coloured icon glyph, no background] [name] [🔥n] … [7 day cells]. Cells ~24pt (`@ScaledMetric`), today's cell outlined in the habit colour until done, then filled; past cells filled by that day's state (simple: habit colour; multi-state: green/orange/red; avoidance: red when slipped) or systemGray5. **Whole row is the button** (44pt+ target per HIG) — tap completes/cycles today; long-press menu = Edit / Delete / Log Details; swipe = Edit / Delete. ⓘ leaves the row (details sheet still auto-opens on completion; "Log Details" in the menu re-opens it). `ViewThatFits`: one line when it fits, otherwise name above the grid.
2. Build, sanity-check on Duo sim, install on Dustin's Duo.

## Decision log

- 2026-10-25 — **promoted from prototype to the design.** Dustin on device: "yes that better" after the first cut; then two UX corrections from him, both applied: (1) every square is tappable, not just the selected day (first cut only toggled the selected day via the row — "if I go back in time and try to uncheck it won't unless I'm on that day"); (2) the arrows move the highlight across a grid anchored to today instead of sliding the grid ("could the back arrow actually change the coloured square to that day") — window slides only once the selection leaves the last 7 days. Name tap = selected day; ⓘ dropped from the row (Log Details in the long-press menu; sheet still auto-opens on completion).
- 2026-10-25 — verification rounds (Duo sim + iPad sim, sequential): per-square toggles, multi-state cycle on a past square (green → yellow → red → clear), avoidance slipped/clear, highlight moves and letters stay put, iPad two columns with letter strips aligned to 0.2pt, landscape OK. Fixed from the rounds: (a) name truncated to ~80pt (`layoutPriority(-1)` + Spacer) → name fills free width; (b) AX-XL overflowed the card (58pt cells) → `WeekGridMetrics` caps the scaled base at 32; (c) empty squares ~1.2:1 on the card in both modes → `systemGray5` fill + 1pt `systemGray3` edge; (d) squares before the habit's `startDate` were toggleable while `shouldTrack` hides the habit on those days → disabled + 35% opacity (also fixes the inconsistency, and Dustin's two test habits now show their pre-creation days faded).
- 2026-10-25 — left alone: nav-title accessibility label lags the visible title (system); the whole list still swaps to "Nothing Scheduled" when every habit is pre-creation on the selected day (existing behaviour); empty-day squares are low-contrast by design (they're the "empty" state; the hairline makes them findable).
- 2026-10-25 — created.
