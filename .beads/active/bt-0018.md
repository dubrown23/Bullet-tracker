# Step 2 — Rest grade, targets as settings, Today in progress, back to auto

## Why

The dh → Bullet voice design (shared note `~/Desktop/Personal/dustin-system/memory/in_flight/habits-voice-dh-bullet-2026-10-26.md`, Part A + Part B "Step 2") needs four things from the app that don't depend on dustin-health at all, so they can be built any time while dh builds its Step 1:

- **Rest** — a fourth state beside Done / Partial / Tried for Workout. Neutral in `HabitWinRule`: not a win, not a miss, the streak carries through. Only when Dustin calls it ("rest day today", or a tap); never automatic. The widget shares the rule.
- **Targets as settings** on graded habits: Diet (protein ≥, calorie low–high), Workout (minutes, steps). Change 1,900 → 2,000 in the habit's settings, no Xcode. Synced by iCloud. `bt-0017` left them as constants in `Sync/HabitGrading.swift` (`DietTargets`); the grading functions keep their signatures.
- **Today in progress** — live numbers, no colour until a target is hit, red only after midnight (Part A "Today, before the day is over"). Same idea the app already uses for avoidance habits ("clean so far").
- **Back to auto** — a way to clear a manual grade so the automatic one returns. Needs an entry-level **source marker** (manual vs automatic) and probably an **edit time**; both additive (`bt-0007` lesson: never loosen or remove from the schema). The same additive change is what lets `dedupeEntries` prefer a meaningful row once rows can differ (`bt-0017` Decision log).

Step 3 (the real sync) joins this with dh's Step 1. dh's Step 1 went live and passed the phone voice test 2026-10-27.

## Plan (design pass 2026-10-27; Dustin's go with three additions, same day)

### Dustin's three additions (2026-10-27)

1. **"Back to Automatic" only on or after the habit's go-live day** (`gradingSince`). Old entries count as hand, so without this guard the button would appear on historical days and pressing it would delete a real grade. Hidden before go-live in both the long-press menu and Log Details.
2. **Only the iPhone runs the automatic grader.** The iPad (and anything without the phone's Health steps) shows grades but never writes, removes or changes auto entries; otherwise its lagging step count could write a lower grade or remove today's yellow, and the newest-edit cleanup rule would keep the iPad's version. Hand taps on the iPad work as normal. Pass check: Run now on the iPad writes nothing.
3. **Grading stays Off on the real Diet and Workout in Step 2.** Test Diet / Test Workout only. Dustin switches the real ones on (which stamps the go-live day) when Step 3 brings real data.

### Rules carried in

- Schema changes are **additive only**: new optional fields, one new enum case. Nothing renamed, retyped or removed (`bt-0007`).
- Grades apply **from the go-live day forward**. The go-live day is stored per habit; days before it are never touched.
- **One entry per habit per day**: every write goes through `HabitStore.setCompletion` / `updateEntryDetails`; the cleanup pass from Step 0 runs after every sync, with a sharper survivor rule (below).
- **Overrides win**: an entry marked hand or voice is never rewritten by the automatic grader until Dustin puts it back on auto.
- Install the new build on **both devices before** setting any Rest or switching grading on: an older build can't read the new state value.

### Data (all additive)

`HabitEntry` (two new optional columns):
- `source: String?` — `"auto"` / `"hand"` / `"voice"`. `nil` = written before this bead = treated as hand (history stays exactly as set).
- `editedAt: Date?` — set on every write from now on.

`Habit` (seven new optional columns, `nil` = built-in default so nothing needs migrating):
- `gradingKind: String?` — `nil` (off) / `"diet"` / `"workout"`. Which rulebook and which targets this habit carries. Also the "kind" the app tells dh in Step 3.
- `gradingSince: Date?` — the go-live day; set to today when `gradingKind` is switched on, cleared when switched off.
- `targetProteinGrams: Double?` (180), `targetCalorieLow: Double?` (1,900), `targetCalorieHigh: Double?` (2,200), `targetWorkoutMinutes: Double?` (30), `targetSteps: Double?` (10,000).

`CompletionState`: `case rest = 4`. Int16-backed like the others.

`DayFacts` (Swift struct, not schema): add `workoutMinutes: Double?`. `nil` = the source doesn't know (so a day can't be marked Tried on steps alone).

JSON backup (`BackupManager`): the same fields added to `HabitData` / `HabitEntryData` as optionals with `decodeIfPresent`, so old backups still restore and new backups still open in the old build.

### 1. Rest

- **Where it's set:** long-press a Workout-graded habit's row → **"Rest Day"** (shows "Clear Rest Day" when already set); and the Log Details sheet's "How'd it go?" picker gets a fourth row, **Rest**. Not in the tap cycle (a tap stays done → partial → tried → clear). Only habits with `gradingKind == "workout"` offer it.
- **What it looks like:** grey square (`AppTheme.rest`, system grey) with a small "zzz" mark when selected; widget tile grey with a zzz badge; Journal gets a **Rest** section beside Completed / Tried / Slipped; PDF export labels it Rest.
- **Rule:** `HabitWinRule.isWin` → false for rest; new `HabitWinRule.isNeutral(state:)` → true for rest. Streaks skip a neutral day the way they skip an unscheduled day (current, best, overall); completion rate, batch stats and heatmap drop the day from both numerator and denominator; the Today subtitle and widget summary drop the habit from "N of M done" that day. `isLogged` stays true so the square fills.
- Widget tap on a rest tile clears it (same as the end of the cycle). Source becomes hand.

### 2. Targets as settings

- Edit Habit / New Habit: a new **Automatic Grading** section under Completion Style, shown for Multi-State habits only. Picker **"Graded by": Off / Diet / Workout**.
  - Diet reveals: Protein at least __ g · Calories from __ · Calories to __.
  - Workout reveals: Workout minutes __ · Steps for partial __.
  - Footer: "Grading starts today. Earlier days stay as you set them."
- Values live on the habit, so iCloud carries them to the iPad. Blank field = built-in default.
- `DietGrade` / new `WorkoutGrade` read the habit's targets (a `GradingTargets` value built from the habit, defaults filled in). Signatures stay pure functions over numbers.
- His Workout habit must be Multi-State for this; if it's Simple today, switch it on the same screen (past ticks stay green).

### 3. Today in progress

- **Live numbers:** on today's row of a graded habit, a caption under the name: Diet "40 / 180 g · 600 cal"; Workout "6,420 steps" (or "45 min · 6,420 steps" once minutes exist). Fed by `HabitSyncEngine.liveFacts` (observable, in memory), refreshed when the app becomes active and on a new **pull-to-refresh** on Today.
- **Colour rule for today** (automatic entries only): success/partial → write the entry (source auto); neither → no entry (square stays uncoloured; if an auto entry existed it is removed — "drop back"). Hand/voice entries are left alone.
- **After midnight:** the grader's window is `max(gradingSince, today − 7)…today`. A past day with no hand/voice entry gets the full grade, including Tried (red). A past day where the source knows nothing (Workout minutes `nil`) is left blank rather than marked red.
- Steps for any day in the window come from Apple Health in the app (`HealthSteps.steps(on:)`). Until Step 3 the only real source of Diet numbers and workout minutes is the fake one in debug builds, so on a normal build the visible change before Step 3 is: steps so far on the Workout row, yellow at the step target.

### 4. Back to auto

- Every tap, cycle, widget tap and Log Details save now writes `source = "hand"` + `editedAt`. The grader writes `"auto"`. Step 3's inbox writes `"voice"`.
- Long-press menu on a graded habit's row: **"Back to Automatic"**, shown when the selected day's entry is hand/voice. Log Details shows the same button plus a line "Set by hand, 3:12 PM" / "Set by voice" / "Automatic".
- Action: delete that day's entry and grade the day again right now from what's known (today: live facts + steps; past: the source). If nothing is known the day stays blank until the next sync fills it.
- Cleanup survivor rule becomes: hand/voice beats auto → newest `editedAt` → smallest id. All three sync with the row, so every device picks the same survivor; still never deletes unless it sees two or more rows.
