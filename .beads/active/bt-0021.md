# Diet + Workout rows — say the mode, show what dh knows

Design pass on the two graded habits only. **Mock-ups first; no code until Dustin says go.** The mock-ups below were built from his real day (2026-10-27: Weighted incline walk 66 min, Workout B — Full Body 23 min / 13 sets, one meal so far) and are the proposal, not the decision.

## Why

The dh sync works (`bt-0019`), but Dustin can't follow what the Diet and Workout rows are doing. In his words (2026-10-27):

1. **Auto vs manual is invisible.** He can't tell whether Diet or Workout is coloured by the app, by him, or by voice, or how to hand it back. Only these two habits have an automatic mode, and the row itself should say which mode it's in ("Auto" vs "Set by you") and how to get back to Auto. Code check: the mode exists only as a "Graded: Automatic / By hand / By voice" line inside Log Details, and "Back to Automatic" is a long-press item that appears only when a hand/voice row exists. Nothing on the row says which.
2. **The details don't use what dh knows.** Code check: the sync already writes dh's session names + minutes into the Workout row's details (`HabitSyncEngine.autoDetails`), but the Log Details form can't show them. The form's type chips are six home-made buckets (`"Cardio", "Strength", "Functional", "Core/Pre-Hab", "HIIT/Jump", "Other"`, `HabitCompletionDetailView.swift:46`), not Apple Watch types, so "Weighted incline walk" lights nothing; the duration chips compare against `"60"` and the sync writes `"89 min"`, so nothing lights there either. The stored values do survive a Done (the form loads them into its state at lines 306–307 and saves them back unchanged, Dustin's correction 2026-10-27); the only problem is that nothing lights up. dh's facts also carry a `category` (walking / running / cycling / strength / hockey / swimming / other) and a `set_count` per session that the app ignores.
3. **Diet details should list the day's meals** (name, calories, protein), kept separate from any note he adds by hand or by voice so neither wipes the other. This is also how meals and calories show inside Bullet. No separate health screen. Code check: Diet rows carry no details today; a voice note appends to the notes field; meals appear nowhere in Bullet except the day-total caption.

## What dh sends (the contract this bead uses; checked against production 2026-10-27)

`op=facts`, per day:

- `meals { count, calories, protein, carbs, fat, names[], items[] }`. **`items` is new (live 2026-10-27), in time order:** `{ id, name, calories, protein, carbs, fat, logged_at }`. A missing number is `null`, not 0 → shown as a dash. `logged_at` is UTC (`2026-10-27T14:05:22.397+00:00`, fractional seconds present) → parsed as a time, shown local (10:05 AM).
- `workouts { count, minutes, sessions[ { name, category, minutes, set_count, started_at } ] }`. The Apple activity identifier (`classification` in dh) and per-set reps / weight are in dh but not sent.

## Where the dh data lives (answer to Dustin's question before go)

**Same column, one new key, no schema change.** `HabitEntry.detailsJSON` already holds a JSON object keyed `notes` / `types` / `duration` / `intensity` / `bookTitle` / `pagesRead` / `mood`. The sync adds one more top-level key, `health`, next to them:

```json
{ "notes": "felt strong",
  "types": ["Cardio", "Strength"], "duration": "89 min", "intensity": 3,
  "health": { "sessions": [ { "name": "Workout B — Full Body", "category": "strength",
                              "minutes": 23, "sets": 13, "start": "2026-10-27T15:17:08Z" } ],
              "meals":    [ { "id": "9d6e…", "name": "1.5 protein coffees", "calories": 168,
                              "protein": 30, "carbs": 0, "fat": 0, "at": "2026-10-27T14:05:22Z" } ] } }
```

No timestamp in the block (Dustin, 2026-10-27): one would differ on every run, so every graded row in the 7-day window would be rewritten and pushed through iCloud each time the app opens.

Why this answers the iPad question:

- **An iPad on the old build reads these rows exactly as before.** `HabitEntry.decodeDetails` (`Data/Models.swift`) picks the case by which keys are present (`types` → workout, `bookTitle` / `pagesRead` → reading, `mood` → mood, else notes) and ignores any key it doesn't know. A Diet row `{ "notes": …, "health": … }` decodes as notes; a Workout row with `health` decodes as workout. Nothing changes in the model, so there is nothing for CloudKit or SwiftData to migrate (the `bt-0007` lesson: never change the shape of a live synced column).
- **The old build's Workout form gets better, not worse:** `types` will now hold chip names only ("Cardio", "Strength"), so its chips light.
- **One known gap:** an old-build iPad that taps Done on such a row re-encodes from its typed enum and drops the `health` key. The iPad is read-only for the sync by rule, and the iPhone's next run (every day in the 7-day window plus changed days) writes the key back. Days outside that window keep whatever is stored, so a hand edit on an old iPad on an old day loses the list for that day. Acceptable; it ends when the iPad is updated.
- **In the new build** `HabitEntryDetails` is unchanged; `HabitEntry` grows a second computed accessor, `health: HealthSnapshot?` (Codable, tiny), over the same string, and the `details` setter preserves the `health` key when it re-encodes. So Done, a voice note (`mergeDetails`), and the chips all write through `details` and can never touch the dh block; the sync writes `health` and never touches `notes`, `intensity` or the state.
- **Who writes `health`:** only the sync, only on the iPhone, for every row of a graded habit in the days it grades — override rows included (facts aren't a grade; state and source are left alone). When today has no row yet (Diet in progress, blank), Log Details reads the engine's live facts for today; after midnight a row exists and carries the snapshot.
- **How `health` is written (Dustin's two fixes, 2026-10-27):**
  1. **Only when it changed.** The sync builds the day's snapshot from the facts and compares it with the row's stored `health` (sessions and meals, value for value). Equal → no write, no save, nothing for iCloud to carry. Different → write. This is why the block carries no timestamp.
  2. **Through its own write, not `HabitStore.updateEntryDetails`.** That path sets state, details, `source` and `editedAt` together (`HabitDataRepository.swift:205–208`), so on an override row it would flip the mode to "Set by you" or move the "Set by you, 2:14 PM" time. New `HabitStore.setHealth(for:on:snapshot:in:)` sets only the `health` key inside `detailsJSON` and leaves `completionState`, `source`, `editedAt` and every other details key exactly as they are. It never creates a row: no row → nothing to attach to (today's live facts cover the sheet). **Test:** a hand-set row (source `hand`, a fixed `editedAt`) keeps both unchanged after a sync whose facts change its meals; the `health` block changes, the notes don't. A second test: the same facts twice → the second run writes nothing.
- **Workout chips vs sessions:** the sync lights chips from dh's category (walking / running / cycling / swimming / hockey / team → Cardio; strength → Strength; other → Other) by adding to `types`, never removing a chip Dustin added. On the first run it also drops the old session names out of `types` (anything not in the six chip names). `duration` keeps the dh total as text, as today.

## Proposal (mock-ups, awaiting go)

### Today row

Before (today, real numbers):

```
🍴 Diet                             ▪ ▪ ▪ ▪ ▪ ▪ ◻
   30 / 180 g · 168 cal
🏃 Workout                          ▪ ▪ ▪ ▪ ▪ ▪ ■✓
   89 min · ··· steps
```

After, Auto:

```
🍴 Diet                             ▪ ▪ ▪ ▪ ▪ ▪ ◻
   Auto · 30 / 180 g · 168 cal
🏃 Workout                          ▪ ▪ ▪ ▪ ▪ ▪ ■✓
   Auto · 89 min · ··· steps
```

After, once he has tapped or spoken a grade (e.g. "call diet partial"):

```
🍴 Diet                             ▪ ▪ ▪ ▪ ▪ ▪ ■◐
   Set by voice · 30 / 180 g · 168 cal   (Back to Auto)
```

- The caption line (today only, these two habits only) starts with the mode: **Auto**, **Set by you**, **Set by voice**. The numbers stay.
- When the mode is not Auto, a small **Back to Auto** button sits at the end of the caption line. One tap: the hand/voice row is dropped and the day is graded again right now (same code path as the long-press item, which stays).
- Taps on the name and squares keep doing what they do (cycle Done → Partial → Tried → clear). The first such tap flips the caption to "Set by you".
- On a past day the row has no caption (as now); mode and Back to Auto live in Log Details.

### Log Details — Workout

Before (today, real row written by the sync):

```
Log Details                                   Done
🏃 Workout · Monday, Oct 27
How'd it go?   (•) Success ( ) Partial ( ) Tried ( ) Rest
Graded         Automatic
Workout Type   [Cardio] [Strength] [Functional] [Core/Pre-Hab] [HIIT/Jump] [Other]   ← none lit
Duration       [15 min] [30 min] [45 min] [60 min] [75 min] [90 min]              ← none lit
Intensity      1 2 (3) 4 5
Notes          (empty — the 11:34 voice note went to the Journal, no row existed yet)
Clear Entry
```

After:

```
Log Details                                   Done
🏃 Workout · Monday, Oct 27

Auto · Done                                        ← mode first; "Set by you, 2:14 PM · Partial (Back to Auto)" when overridden
Graded from today's workouts in Dustin's Health.

How'd it go?   (•) Success ( ) Partial ( ) Tried ( ) Rest

From Dustin's Health
  Weighted incline walk      66 min              10:10 AM
  Workout B — Full Body      23 min · 13 sets    11:17 AM
  Total                      89 min

Workout Type   [Cardio ●] [Strength ●] [Functional] [Core/Pre-Hab] [HIIT/Jump] [Other]
Intensity      1 2 (3) 4 5
Notes          (yours + voice notes, appended, never overwritten)
Clear Entry
```

- "From Dustin's Health" is read-only, from the row's `health` block (today: the live facts). It is the "sets where it fits" (dh sends the count, not the reps).
- Type chips are lit from dh's category (mapping above). The finer chips (Functional, Core/Pre-Hab, HIIT/Jump) can't be told apart from the category alone; he can add them by hand and they stay.
- Duration chips disappear on a day dh has sessions; the minutes are the dh total. On a day with no dh sessions the form is exactly today's form.
- The sync owns the dh list and the chips it lit. He owns intensity, any chip he added, and notes.
- Changing "How'd it go?" makes it Set by you (as now) and the mode line updates in place.

### Log Details — Diet

Before: the sheet only exists if the habit has a details kind; the meals are nowhere in Bullet. With a kind of Notes it shows: header, How'd it go?, "Graded: Automatic", Notes, Clear Entry.

After (today, real):

```
Log Details                                   Done
🍴 Diet · Monday, Oct 27

Auto · in progress                                 ← no colour until midnight; "Set by voice, 1:02 PM · Partial (Back to Auto)" when overridden
Protein 30 / 180 g · Calories 168 of 1,900–2,200

Meals from Dustin's Health
  10:05 AM  1.5 protein coffees            168 cal · 30 g
  Total                                    168 cal · 30 g

How'd it go?   ( ) Success ( ) Partial ( ) Tried

Notes          (yours + voice notes; the meals list never touches this)
Clear Entry
```

- One line per meal from dh's `items`, in the order he logged them, time shown local. A missing calorie or protein value shows as "—" (e.g. `— cal · 30 g`). The Total line is dh's day totals.
- The list is drawn from the row's `health` block (today: the live facts), apart from `notes`, so a note (hand or voice) and the meals can never wipe each other.
- Log Details is always offered for Diet and Workout (graded habits), whatever their details kind.
