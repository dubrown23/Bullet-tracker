# iPhone Duo + iOS 26/27 modernization — Wave 2: Duo layout

## Why

`bt-0008` confirmed on Dustin's physical Duo (screenshot 2026-10-24, 951×669 pt unfolded): the system keeps the tab bar as a right-hand vertical rail in both postures (so `.sidebarAdaptable` is a no-op there — fine, it's the system's call), but every screen is still the compact phone layout stretched across the width. Today shows 9 of 11 habits as edge-to-edge rows with ~1,500 px of nothing between the name and the ⓘ button. Dashboard the same. Several views also carry fixed widths that squeeze at the folded 466 pt width.

Dustin's standing rule (2026-10-24): **use Apple's guidelines whenever possible.** HIG → Layout: design for the full-screen size first and only switch to compact when the full layout no longer fits; adapt with size classes, not device checks; test at the common sizes. SwiftUI's tools for that are `@Environment(\.horizontalSizeClass)` and `LazyVGrid` with `GridItem(.adaptive(minimum:))`.

## Out of scope

- Toolbar restructuring (Today's "+" jumping between the rail and a bottom capsule), glass, text styles, accessibility labels → `bt-0010`.
- Widget → `bt-0011`.
- Tab bar placement — system-controlled on the Duo.

## Plan

1. `Utilities/AdaptiveLayout.swift` (new) — one small helper: a `PairedRows` view that lays a collection out as single rows in compact width and as two-per-row (with a vertical divider) in regular width. Keeps `List` as the container (system separators, insets, grouped style) instead of swapping to a custom card grid.
2. `TodayView` — habits section uses `PairedRows`; progress row unchanged.
3. `HabitDashboardView` — "By Habit" section uses `PairedRows` (NavigationLink per cell).
4. `IconSelectorView` — `GridItem(.flexible()) × 6` → `GridItem(.adaptive(minimum: 44), spacing: 12)` so the grid fills whatever width it has.
5. `HabitCompletionDetailView` — intensity picker `.frame(width: 200)` → own `Section("Intensity")` with the segmented picker filling the row; pages field `.frame(width: 60)` → `minWidth/maxWidth`.
6. `DayJournalView` — move the quick-add note field into the `List` as its first section (Reminders-style "add" row). Removes the seam between the material header and the list, and gives the field proper insets. `DayCell` fixed 44×56 → `minWidth/minHeight` so it can grow.
7. Build; verify on Duo sim (folded) + install on Dustin's Duo for the unfolded check; ship.
