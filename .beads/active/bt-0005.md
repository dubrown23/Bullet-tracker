# Repo-layout cleanup — Xcode-project surgery + Pile A regression fix

## Why

Started as the second half of `bt-0001` flag #5 — move `Assets.xcassets` + `Bullet Tracker.entitlements` out of the legacy nested `Bullet Tracker/` folder so the folder can be deleted. Design pass surfaced two findings:

**Finding 1 (good):** The nested `Bullet Tracker/` group is a `PBXFileSystemSynchronizedRootGroup` (Xcode 16's auto-synced folder feature) — no list of individual file references to surgically rewrite. Drag-and-drop in Xcode UI handles the move cleanly; no hand-editing of `project.pbxproj` needed.

**Finding 2 (bad — `bt-0006` regression):** `bt-0006` deleted 6 markdown files from `Documentation/` via `git rm` without checking `project.pbxproj` first. All 6 files remain registered in the main-app target's Copy Bundle Resources build phase + as `PBXFileReference` entries inside a `Documentation` `PBXGroup` (lines 18, 37–40, 49 reference build files; lines 295–307 define the group; line 461 region lists them in Resources). Build may warn or fail outright on next attempt. Cleanup is mechanical (right-click → Remove Reference in Xcode for each of 6 files + the now-empty group) and folds naturally into the same Xcode session as the Pile B move. Folded into this bead's scope rather than reopening `bt-0006`.

The `ds-0040` phase-gate hook doesn't gate Xcode UI edits (Dustin operates Xcode directly, Claude observes), so `scope_files` only needs to cover Claude-side writes — `STATUS.md` for the post-ship update. `project.pbxproj` edits go through Xcode.

## Out of scope

- Swift source changes.
- Reorganizing any folder beyond the nested `Bullet Tracker/` removal.
- Re-adding any of the 6 deleted markdown files to the build — they were vestigial; `bt-0006` intent was to remove them, this bead completes that cleanup.

## Plan

Dustin drives Xcode for steps 1–7; Claude does step 8 + verification.

1. **Verify current build state.** Cmd+Shift+K (clean) → Cmd+B (build). Report: clean / warnings / error. Catches whether the Pile A dangling refs warn-only or hard-fail.
2. **Remove dangling Documentation references.** In Xcode's file navigator, expand the `Documentation` group. The 6 files inside should appear in red (missing on disk). Right-click each → Delete → **"Remove Reference"** (NOT "Move to Trash" — files already gone). Files: `Bullet Track - Context.md`, `Bullet Track - Overview.md`, `Bullet Track - protocol`, `Bullet Track - update log.md`, `Bullet Tracker - Future Optimizations`, `feature list.md`.
3. **Remove the now-empty Documentation group.** Right-click `Documentation` group → Delete → Remove Reference.
4. **Re-verify build.** Cmd+B. Should be clean (no Pile A warnings/errors).
5. **Move the 2 files out of the nested folder.** Expand the `Bullet Tracker` group. Drag `Assets.xcassets` and `Bullet Tracker.entitlements` up to the project root in the navigator. Xcode auto-rewrites `project.pbxproj` (synchronized-group references → conventional file references; `CODE_SIGN_ENTITLEMENTS` paths at lines 746 + 776 rewrite from `Bullet Tracker/Bullet Tracker.entitlements` to `Bullet Tracker.entitlements`).
6. **Remove the now-empty Bullet Tracker group.** Right-click `Bullet Tracker` group → Delete → Remove Reference.
7. **Final build + device run.** Cmd+B clean, then run on device. Confirms code-signing still works with the new entitlements path + asset catalog still loads.
8. **Cleanup empty folder on disk.** Claude: `rm -rf "Bullet Tracker/"` via Bash (not gated). Verify `project.pbxproj` diff: synchronized-group entry for "Bullet Tracker" removed, entitlements paths rewritten, no remaining references to nested folder, no remaining references to deleted Documentation files.
9. **Update STATUS.md and ship.**
